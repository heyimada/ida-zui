# ida-zui UX re-audit

Scope: main at `873f3cc`, re-checking every row of `docs/UX_AUDIT.md` against the implementers' "Resolved" notes, then a fresh pass as an IDA veteran. The build (`cargo build --workspace --bins --examples`, `IDASDKDIR` set) was warning-free in our crates and `cargo test -p ida-zui` passes (177 tests).

How the evidence was gathered, under the same rules as the first audit: only the app window is captured (PrintWindow through `scripts/ui-capture.ps1`), only the in-app automation channel drives it, the system clipboard is never read or written (every "clipboard" value below is the in-process buffer dumped through `clipdump`/`clipassert`), every run uses its own `-Work` directory (`raudit*`, `ctx`, `sel`, `edit`, ...) so the user's settings were untouched, Lumina push is never triggered, and no `ida-zui`/`ida-host` process was left running. Two background batches of the implementers' scripts were stopped by the harness for memory pressure; every script named below was then re-run one at a time. `ui-dragscroll.ps1` and `ui-graphdrag.ps1` were **not** re-run (the batch was killed before reaching them); the H2 drag-autoscroll claim rests on the implementers' artifacts only.

Fresh screenshots from this re-audit: `artifacts/ui/r_*.png` (dark), `rl_*.png` (light, compact rows), `rw_*.png` (welcome), `x_*.png`, `y*_*.png`, `z*_*.png` (targeted repros). Implementer scripts re-run by me, with their exit codes: `ui-contextmenu` 0, `ui-selection` 0, `ui-edit` 0 (10 line assertions + "7 bytes differ"), `ui-hex` 0, `ui-casts` 0, `ui-tables` 0, `ui-tabs` 0, `ui-panes` 0, `ui-tabmenu` 0, `ui-float` 0, `ui-marks` **1 on the first run** (both `clipassert`s read an empty clipboard), 0 on an immediate re-run.

### Verdict

R2, R3, R4, R5, R6, R7 and R9 are fixed; R8 is as far as it can go on this sample. R1 is fixed for tabs and panes but not for floating windows, where the main window never takes the driver back and a bookmark goes to the wrong function. N1 is a new blocker for anyone who closes the app with the mouse: it loses the session without asking. Fix N1 and the floating-window half of R1 before the next round.
